Topic: CL325

C2-NRED Module Configuration

This configuration dialog contains basic network and security settings to get your C2-NRED module ready for a Node-RED ® project. Once this configuration is loaded to the PLC, you may create a Node-RED project which runs on the C2-NRED module separate from the ladder logic running on the CLICK CPU.

Network Address Configuration: Set up your Network Address Configuration to configure the programming IP address for the Node-RED Environment. It is recommended that you assign an IP address or use a fixed IP address. This is because Node-RED is designed to act as a web server allowing other devices to connect. If you have a Dynamic IP, those devices won’t be able to connect to Node-RED after an IP address refresh.

If you choose to configure your network switch for IP/MAC ID binding, this will give you the advantage that all the devices can use DHCP and the configuration of the IP addresses will be centralized in the router. To find the MAC ID of the C2-NRED module, look in system registers SD327-332 for a card in slot 0, or if your C2-NRED card is in slot 1, look at SD427-432.

DNS Server: Configure the DNS Server. If you intend to use Node-RED to connect to any internet addresses by URL, you will need to specify a public DNS server. A common choice is Google’s server at 8.8.8.8 or 8.8.4.4.

Enable Node-RED: Be sure to enable Node-RED. If it is NOT enabled, the OK LED will flash quickly (2.5 Hz) and the ERR LED will flash slowly (1 Hz).

Disabling the Node-Red module will close all ports and disable any processes. This is the default setting to ensure the module is configured as desired with appropriate security prior to enabling access to the module.

Enable HTTPS: Enabling HTTPS will make the Node-RED administration window accessible using HTTPS secure communication. If you intend to access Node-RED using a static IP and make it available over the internet (as opposed to a private network behind a firewall), you should buy a certificate from a trusted provider and install the certificate and private key file. Popular certificate providers include:

  • LetsEncrypt

  • DigiCert

  • Entrust

  • GlobalSign

It is possible to generate a self-signed certificate using a tool like OpenSSL. If you do so, you will need to create 3 files: a certificate, a private key, and a root certificate. The root certificate file will need to be installed in your PC's OS. This will allow any PC with the root certificate to access the Node-RED server, but other PCs will not be able to access it.

Security Options: Security parameters are not applied immediately with run-time edits. Security changes take effect when the processor state changes from Stop to Run mode.

Enable Response to Ping from other devices: Enabling will allow the C2-NRED to respond to a Ping command. This will make setup and troubleshooting easier, but it opens an attack vector. We recommend that this setting be disabled on a production system.

Enable user to add nodes from Network: Enabling will turn on the “Manage Palette” feature in Node-RED. This will likely be needed to set up and program your C2-NRED, but should be disabled after the programming is complete on a production system.

Enable Allow List: When enabled, you can configure a list of IP addresses to which Node-RED will respond. It allows individual IP addresses or a range of IP Addresses, and allows up to 32 entries. If an IP address that is not in this list calls an HTTP, WebSocket, TCP, or makes a request to view the dashboard, Node-RED will not respond. This does not apply to the programming interface. If you need to secure access the programming interface, use the Node-RED Accounts feature instead. When Allow List is disabled, Node-RED will respond to any request from any source. For details on configuring the Allow List, see Allow List Setup.

Port Management: Port Management allows you to open additional ports on the Node-RED webserver. This is necessary if you are connecting to servers the don’t use port 80/443, like MQTT or Modbus.

Enable Node-RED Accounts: Enables password protection to the Node-RED programming interface. If this is used without HTTPS properly configured, usernames and passwords will be transmitted in plain text and can be easily discovered using a packet sniffer like Wireshark.

When this is selected, you are allowed to configure up to 8 users who have either read-only or full access to modify flows. Node-RED Accounts do NOT apply to the Node-RED Dashboard, or the APIs created using nodes in the Network Group e.g. “HTTP IN”, “TCP IN”, “HTTP REQUEST”.

When this is NOT selected, ANY USER who has access to the C2-NRED IP address will have full admin rights to modify the Node-RED programs.

Note:It is highly recommended that you ensure the IP Address for the C2-NRED module is secured behind a firewall and NOT available outside your organization unless you properly configure HTTPS and secure access to the device.

When you download your CLICK Project to your PLC, these settings will take effect.

Time (RTC): The C2-NRED module shares a clock with your CLICK PLUS PLC. Be sure to update the time in the PLC. If the time is wrong, it will impact your ability to download 3rd party modules into the Node-RED environment. Those modules are signed and if your clock is not set, you will get CERT_NOT_YET_VALID errors.
